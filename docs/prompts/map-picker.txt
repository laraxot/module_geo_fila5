## 1. Business Goal

Standardize Geo Filament fields so they are stable, reusable, and simple in both frontoffice and backoffice.

Required outcomes:

- one real Filament state path, usually `location`
- canonical persistence on `location`
- `location` stored as JSON/array cast on the owner model when a real column exists
- backward compatibility with `latitude` and `longitude` columns when they exist
- UI and JS aligned with Leaflet naming `lat` / `lng`
- reusable sibling components, not a hierarchy

---

## 2. Canonical Data Contract

`CoordinatePicker::make('location')` must work on a single composite payload.

Canonical payload:

```json
{
  "lat": 45.4642,
  "lng": 9.19,
  "address": "Via Roma 1, Milano, Italia",
  "provider": "nominatim",
  "address_details": {},
  "street": "",
  "street_number": "",
  "city": "",
  "postcode": "",
  "state": "",
  "province": "",
  "country": "",
  "country_code": "",
  "suburb": "",
  "display_name": "",
  "raw": {}
}
```

Rules:

- UI, Alpine, Lit, and Leaflet use `lat` and `lng`
- legacy DB sync remains:
  - `latitude = location.lat`
  - `longitude = location.lng`
- if input arrives as `latitude` / `longitude`, normalize once
- do not maintain parallel coordinate contracts longer than necessary

---

## 3. Architectural Rules

- Every Geo field extends `Modules\Xot\Filament\Forms\Components\XotBaseField`
- `CoordinatePicker` uses one unified `statePath`
- Geo fields are siblings, never deep inheritance
- `CoordinatePicker.php` should stay thin and document its runtime Blade owner in comments
- shared config and server methods live in `HasCoordinatePicker`
- Livewire is server authority for persistence, geocoding, and reverse geocoding
- Alpine is a thin adapter only
- Lit handles map UI and emits semantic events
- if a JS file exceeds about 200 lines, split it into smaller helpers/modules

---

## 4. Filament Custom Field Contract

Inside the Blade field view:

- read state using `$getStatePath()`
- obey Filament state binding modifiers
- use `$getKey()` with `callSchemaComponentMethod()`
- keep Leaflet isolated from Livewire DOM churn

Do not:

- invent alternate ids for schema method calls
- duplicate state into extra Alpine variables without reason
- bind the map in ways that create feedback loops

---

## 5. Owner Model Persistence

For the owner model, for example `Ticket`:

1. `location` must be in `$fillable`
2. `location` must be cast as `array` or JSON equivalent when the column exists
3. `location` is the source of truth
4. `latitude` and `longitude` remain only for retrocompatibility
5. sync legacy columns explicitly during save/hydration

Expected sync:

```php
$model->latitude = $location['lat'] ?? null;
$model->longitude = $location['lng'] ?? null;
```

If the table does not have a physical `location` column yet, the field contract still stays centered on `location`, and the bridging logic must map it safely to existing persistence columns.

## 6. UX Minimum Requirements

Required map controls:

- fullscreen toggle
- explicit geolocation button
- layer switcher with at least 4 layers
- zoom in
- zoom out
- click-to-set marker
- draggable marker with update on `dragend`

Required address search:

- search box above the map
- always visible on mobile
- debounce at `500ms`
- server-side search through Livewire
- max 5 results
- selecting a result updates marker, center, and full `location` payload

Required responsive behavior:

- mobile touch targets at least `44x44`
- mobile search remains visible
- map height responsive, e.g. `50dvh` mobile, `60vh` tablet, configurable desktop
- invalidate Leaflet size on resize, wizard step visibility, and fullscreen transitions

Required structured address data:

- `address`
- `address_details`
- `street`
- `street_number`
- `city`
- `postcode`
- `state`
- `province`
- `country`
- `country_code`
- `suburb`

Normalized source aliases accepted during mapping:

- `street` / `road`
- `street_number` / `house_number`
- `city` / `town` / `municipality`
- `province` / `county`
- `suburb` / `city_district` / `neighbourhood`

## 7. Search and Reverse Geocoding

Server-side only:

- `searchAddress(string $query): array`
- `reverseGeocode(float $lat, float $lng): ?array`

Rules:

- never call Nominatim directly from browser JS
- always send a valid `User-Agent`
- respect rate limiting
- fail silently for UX, but keep code observable and testable
- prefer scoped search such as `countrycodes=it` when appropriate
- event payload emitted by the Lit map should be canonical Leaflet-style:

```js
{
  lat: 45.4642,
  lng: 9.19,
  source: 'click'
}
```

- if temporary compatibility with `latitude` / `longitude` is needed, normalize it once in Alpine or in the shared trait, not across every layer

---

## 8. i18n Requirements

- never hardcode user-facing strings in JS or Blade
- all visible labels come from Geo lang files
- minimum locales: `it` and `en`
- pass translated labels from Blade to Lit as JSON

Useful key families:

- `search_placeholder`
- `use_my_location`
- `locating`
- `fullscreen`
- `close_fullscreen`
- `zoom_in`
- `zoom_out`
- `search_no_results`
- `location_error`
- `geocode_error`
- `layers.street`
- `layers.humanitarian`
- `layers.satellite`
- `layers.topographic`

---

## 9. Performance and Loop Guards

- never update Livewire on `mousemove`
- never update Livewire during drag
- update only on `click`, `dragend`, explicit geolocation success, and search selection
- use a guard such as `_suppressUpdate` to prevent re-entrant loops
- avoid duplicated normalize/mapping logic across PHP, Blade, Alpine, and Lit

---

## 10. Accessibility

- all map buttons must use `type="button"`
- all map buttons must include `aria-label` and `title`
- ESC closes dropdown and fullscreen
- keep a logical tab order
- include a polite live region for coordinates and resolved address
- search input should expose `aria-autocomplete`, `aria-controls`, and `aria-expanded`

## 14. Bad Practices (Extended)

| Avoid | Use Instead | Why |
|---|---|---|
| `LatitudeLongitudeInput extends CoordinatePicker` | sibling pattern with shared trait | deep inheritance breaks DRY and makes overrides unpredictable |
| `id="map"` or `document.getElementById('map')` | `this.querySelector('.map-container')` | IDs are globally unique; multiple maps per page or wizard steps cause conflicts |
| direct Nominatim calls from browser JS | Livewire server methods `searchAddress()` / `reverseGeocode()` | exposes IP to third party, bypasses User-Agent policy, violates Nominatim ToS |
| hardcoded UI strings in JS or Blade | Geo lang files passed as JSON to Lit | breaks i18n, blocks translations, maintenance debt |
| Livewire updates on `drag`, `mousemove`, `move` | update only on `dragend`, `click`, explicit user intent | causes cascading re-renders, infinite loops, freezes map |
| `@entangle` on Lit component properties | one-way props-down + events-up pattern | `@entangle` with Lit triggers infinite Livewire re-render cycles |
| giant JS files > 200 lines | split into `layers.js`, `controls.js`, `events.js`, etc. | violates KISS, impossible to unit-test, hard to review |
| deleting commented picker alternatives | preserve them in consuming widgets | they document the evaluated API surface for future maintainers |
| CDN/unpkg references for Leaflet or assets | bundle assets locally via Vite | CDN drift breaks offline, changes behavior between environments |
| using `lat`/`lng` and `latitude`/`longitude` in parallel across layers | normalize once at Alpine or trait boundary | parallel naming contracts cause silent bugs and mapping errors |
| calling `map.invalidateSize()` inside Livewire lifecycle hooks unconditionally | call only after DOM visibility confirmed | premature invalidate on hidden container returns wrong tile sizes |
| binding Filament state to JS via extra Alpine intermediary variables | read directly from `$wire.$get($getStatePath())` | creates stale state, desync between Livewire and JS |
| catching geocoding exceptions globally and swallowing them | log to `Log::warning()`, expose to `$errors` in testable methods | silent failures make integration testing impossible |
| `map.setView()` on every Livewire render | only move map on explicit user interaction or first mount | causes jumpy UX when component re-renders after unrelated state change |
| Hardcoding `#0066CC` colors or `heroicon-o-...` names in JS | Makes i18n and theming impossible, couples to single theme | Pass colors/icons from Blade via dataset or lang JSON, use `icon-white` for header controls |
| `pointer-events: none` on map wrapper or `opacity: 0` overlay | Blocks interaction with map controls, causes "invisible controls" bug | Ensure `pointer-events: auto` on interactive elements, use proper `z-index` and `bg-white` wrapper where needed |
| Updating Livewire on every marker drag tick | Floods server, race conditions, poor UX | Update on `dragend` only; debounce rapid events |
| Mixing `latitude`/`longitude` and `location` in same model without sync | Source-of-truth ambiguity, silent data divergence | Keep `location` as source of truth; sync legacy columns explicitly in model observer or save method |

## 15. Best Practices (What to Do)

| Practice | Implementation |
|---|---|
| **Single source of truth** | Keep `location` as canonical payload. Legacy `latitude`/`longitude` are secondary, synced explicitly. |
| **Sibling components, not hierarchy** | All Geo fields extend `XotBaseField`. Share behavior via `HasCoordinatePicker` trait. No deep inheritance. |
| **Server-side geocoding** | `searchAddress()` and `reverseGeocode()` live in Livewire actions; never call Nominatim from JS. |
| **Leaflet alignment** | Use `lat`/`lng` in Leaflet and payload; map to `latitude`/`longitude` only at persistence boundary. |
| **Inline SVG markers** | Define `createMapPickerLeafletIcon(L)` returning `L.divIcon({ html: svg })`. No CDN, no external image files. |
| **MutationObserver for wizard steps** | In `coordinate-picker-lit.js`, observe ancestor `class`/`hidden` changes and call `map.invalidateSize()` to fix "blank map after Next" issue. |
| **Debounced server search** | Livewire method `searchAddress()` debounced 500ms; max 5 results; scoped `countrycodes=it` for Italy. |
| **Pass translations to Lit** | Blade renders JSON: `<div id="geo-labels" data-labels="{{ json_encode(__('geo::labels')) }}"></div>`; Lit reads labels from dataset. |
| **i18n keys in lang files** | Never hardcode in JS: use `__('geo::search_placeholder')` in Blade, pass to Lit. Minimum locales: `it`, `en`. |
| **Component-scoped mounting** | Lit component mounts to `this.shadowRoot` or class-scoped element; no global `#map` id. |
| **Mobile-first responsive map** | Map container: `50dvh` mobile, `60vh` tablet, configurable desktop. Touch targets `44x44`. Search always visible on mobile. |
| **Full map controls** | Required: fullscreen toggle, geolocate button, layer switcher (street/humanitarian/satellite/topographic), zoom in/out, click/drag marker, address search. |
| **Graceful failure** | If geolocation fails or Nominatim rate-limits, fail silently with UX indicator, not console errors. |
| **Accessibility** | All buttons: `type="button"`, `aria-label`, `title`. ESC closes fullscreen/dropdowns. Polite live region for coordinates/address. |
| **Quality gates before commit** | Run: `phpstan`, `phpmd`, `phpinsights`, `pest`, `playwright`. Verify both frontend wizard and admin ticket create. |
| **Visual parity verification** | After every change, open URLs in browser: `http://127.0.0.1:8000/it/tests/segnalazione-crea` and `http://127.0.0.1:8000/fixcity/admin/tickets/create`. Use Playwright screenshots to confirm no regression. |
| **Extraction at 200 lines** | If coordinate-picker-lit.js > ~200 lines, extract: `layers.js`, `controls.js`, `events.js`, `geolocation.js`, `invalidate.js`, `normalize.js`. |
| **Use `callSchemaComponentMethod()`** | To invoke picker methods from outside (e.g., reset, center), use `$getKey()` + `callSchemaComponentMethod()` rather than global refs. |

## 16. False Friends (Common Missteps)

| False Friend | Symptom | Why It's Wrong | Fix |
|---|---|---|---|
| **IntersectionObserver will fix blank map** | Map stays gray after wizard "Next" | `IntersectionObserver` only detects viewport intersection, not `class="hidden"` toggles. Hidden elements can be in viewport but still have zero computed dimensions. | Use `MutationObserver` on ancestor class/style, or force `invalidateSize()` on wizard step show. |
| **`SchemaView::make()` is a valid summary component** | Summary step renders empty or throws | `SchemaView` is not an Infolist component; wizard summary requires `TextEntry`, `ImageEntry`, `Section` from `Filament\Schemas\Components` and `Filament\Infolists\Components`. | Use `TextEntry::make()->state(fn (Get $g) => $g('field'))`. |
| **`use Filament\Forms\Components\Section`** | Linter aliases `Section` and causes "Cannot redeclare" or `Section::make()` resolves wrong | In Filament 5, form `Section` is in `Filament\Schemas\Components\Section`, not `Forms`. Linter may alias all three (`FormSection`, `InfolistSection`, `SchemaSection`) and break bare `Section::make()`. | Always `use Filament\Schemas\Components\Section`. Remove other `Section` imports. |
| **Adding `::make()` items to summary schema as `SchemaView` or `Infolist`** | Runtime error or nothing rendered | `getSummarySchema()` expects Infolist components (`TextEntry`, etc.) + `Filament\Schemas` layout components (`Section`, `Grid`). Not `SchemaView`. | Use correct namespaces and component types. |
| **`L.Icon.Default` or unpkg marker icons** | Marker icons missing or blocked by adblocker | Leaflet default icons rely on CDN paths; unpkg assets may be blocked or CORS-failed; inconsistent look. | Use inline SVG via `L.divIcon` with local SVG content (see `createMapPickerLeafletIcon`). |
| **Hardcoding `#0066CC` or `icon-primary` in slim header auth** | Button blends into header or fails UX "Mario Rossi" principle | Slim auth must have visible name, clear affordance, and `icon-white` on blue header. `icon-primary` can be blue-on-blue. | Use `icon-white`, ensure name is prominent, dropdown arrow visible. |
| **CSS `[data-slug="..."]` page-specific overrides** | Styles only work on one page; breaks when reused | Design Comuni uses global component classes; page-specific CSS is an anti-pattern that harms maintainability. | Make CSS component-scoped; use props/attributes for variants, not page names. |
| **Livewire updates on `mousemove`** | Severe server load and lag | Each mousemove triggers a Livewire request; server floods, UI freezes. | Use guards; update only on `click`, `dragend`, explicit events. |
| **Deleting commented picker alternatives** | Future devs can't see evaluated options | The comment block documents considered alternatives; removing it erases intent and learning. | Keep commented list intact as documentation. |
| **`latitude`/`longitude` in payload alongside `location` without clear sync** | Silent data divergence, stale fields | Dual sources of truth lead to bugs where one is updated and the other not. | Normalize once; persist `location` as source; sync legacy columns explicitly with `hasColumn` guards. |

## 18. Quick Checklist Before Commit

- [ ] No hardcoded UI strings in JS/Blade — all labels from `lang/` passed to Lit as JSON.
- [ ] No CDN/unpkg Leaflet assets; marker icons are inline SVG from `resources/svg/`.
- [ ] `CoordinatePicker` uses single `location` state path; legacy columns synced explicitly.
- [ ] JS updates Livewire only on intentional events (`click`, `dragend`, search select), never `mousemove`/continuous drag.
- [ ] `MutationObserver` triggers `map.invalidateSize()` when wizard step visibility changes (depth >= 12 ancestors).
- [ ] `phpstan`, `phpmd`, `phpinsights`, `pest`, `playwright` all run and pass for modified files.
- [ ] Visual parity verified: open both `segnalazione-crea` (wizard) and `admin/tickets/create` in browser and compare to Design Comuni reference.
- [ ] No page-specific CSS selectors; styles are component-scoped and work in any context.
- [ ] Commented picker alternatives preserved in consuming widget (non-negotiable).
- [ ] If JS file grew beyond ~200 lines, extract helpers (`layers`, `controls`, etc.).
